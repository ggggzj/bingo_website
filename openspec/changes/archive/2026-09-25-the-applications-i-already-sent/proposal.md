# Proposal — the-applications-i-already-sent

## Why

The owner runs `~/Desktop/job_dashboard` as a job-search control panel: **94 applications**
(71 applied, 15 closed, 8 saved), **18 rows they wrote by hand**, and **80 archived JD bodies**
(632 KB). It is a working artifact, opened daily, and none of it is in their account.

Origin — `.harness/backlogs/024`, owner request 2026-09-24: *"把这个 dashboard 接进我
bingocareer 的账号中"*.

One part of that folder cannot be reproduced from anywhere. The 18 hand-written rows quote the
employers' own words — `not able to support work authorization sponsorship`,
`doesn't offer visa sponsorship`, `岗位已下架` — and Simplify does not have them, the employer
will not resend them, and two JD bodies are **already gone** (Trustpilot 404'd one day after
applying, Showpad five days after; both recorded in `overrides.js`). Everything else in the
folder can be regenerated by re-running a script. These cannot.

## What Changes

**The line between the two halves is the owner's decision (024, decision 1)** and it is the
shape of this whole change:

| | Owner | Written by |
|---|---|---|
| Company, role, location, ATS, apply link, applied date, JD body | the import | the folder's existing scripts |
| **Status, stage, note** | the account | **the browser** |

- **Three tables** in `lib/db/src/schema/`: `applications` (the machine half, import-owned),
  `application_status` (the human half, account-owned), `application_events` (the append-only
  trail). Applied with `generate` + `railway connect`, the path `replit.md` records — this repo
  has no `push`.
- **An import that runs from the owner's folder against the database**, not through an HTTP
  endpoint. This reuses the database access the owner already has (`railway connect Postgres`,
  the path `replit.md` records) rather than introducing a new way in. It is **not** credential-free,
  and saying so was an error in an earlier draft: a connection string is a broader credential than
  the scoped token `.harness/backlogs/025` describes. What this change avoids is a *new* one.
- **One step appended to the folder's `add_job.py`**, so applying to a job stays a single
  command. That script already chains import → archive JD and prints 完成; this adds push →
  account as a third step. It is **skipped with a printed line, never an error, when the
  database is not configured** — the folder is documented as working offline and must keep
  doing so.
- **Three routes** across the `openapi.yaml` contract (codegen in the same task): list the
  applications, change one's human half, read one's archived JD. Owner-only through the
  `OWNER_EMAIL` configuration seam, answering **404 to everyone else** — the uniform answer
  `routes/new-grad.ts` already gives.
- **A fourth entry in `VIEWS`** (`artifacts/landing/src/pages/dashboard/views.tsx`), which is the
  whole extension point `008` built the rail for.
- **The header states when the import last ran**, because the machine half is exactly as old as
  that.

## What does not change

- **The folder keeps working, offline included.** `import_simplify.py` and `archive_jds.py` are
  untouched and keep producing `applications.js` and `archive.js`, which the import reads.
  `add_job.py` gains exactly one step — the push above — and gains nothing else; with no database
  configured it behaves as it does today. `overrides.js` stops being an input at cutover (its 18
  rows are imported once as the seed of the human half) but the file is not deleted.
  **Owner decision 2026-09-25**, reversing this proposal's first draft, which left the folder's
  scripts alone and cost a second command after every application.
- **`/jobs` still reads no session.** That recorded decision (`replit.md`) is untouched here.
- **`017`'s kanban is not started, moved or redesigned.** This change writes status for one
  account; that ticket's design question — what writes to a tracker for *users* — is untouched.
  The tables here are built so `017` can adopt them: same vocabulary, same trail.

## The decisions this settles

The ticket left six open, each with a recommendation. This proposal takes all six; the owner
reverses any of them by saying so before `/implement`.

| # | Question | Taken |
|---|---|---|
| 1 | Do the folder's charts come across? | **Status counts and days-waiting only.** Pace, location spread and conversion rate do not. At 94 rows a count is a count; a conversion rate is the first step toward the scoring this product killed once. |
| 2 | Rail id and label | **`/dashboard/applications`, "Applications"**, placed after New grad. Rail labels are English today (Growth / New grad / Practice). |
| 3 | How the import runs | **A script the owner runs, straight to the database.** Not an HTTP endpoint. This does not make it credential-free — see design.md; it reuses the database access the owner already has, which is *broader* than the token `025` would introduce. |
| 4 | Do `interview-prep.md` and cover letters travel? | **No.** One prep file exists today; carrying it doubles the schema for one row. |
| 5 | The 6 non-US rows (UK 3, Canada 2, Remote 1) | **They stay.** h1_checker's `011` keeps non-US postings out of the *feed*; these are applications the owner actually sent. |
| 6 | What the folder's board shows after cutover | **Out of this change** — `dashboard.html` is in the owner's folder, not this repo. Captured as a session-todo so two boards do not disagree about status on some Tuesday. |

## Non-goals

- **No write path for local scripts.** After this change, status is changed in the browser and
  the Claude-in-the-folder loop ends there. Restoring it is `.harness/backlogs/025` and needs a
  fourth secret; naming it here is what keeps it out.
- **No per-user tokens, no public write API.** The moment every user gets one, this is `017`'s
  problem, with credential storage, rotation and abuse attached.
- **Not multi-user.** One reader, gated by configuration rather than by a column.
- **No CSV upload in the browser.** The folder already imports CSV; duplicating it here buys
  nothing this year.
- **No score, no match percentage, no predicted outcome.** "Applied 14 days ago, no reply" is a
  fact and is welcome; a probability is not.
- **No change to the extension, `/jobs`, or the feed.**

## Capabilities

### New Capabilities

- `applications-list` — the owner's sent applications in the account: imported from the folder,
  status changed in the browser, every change trailed, the archived JD readable.

### Modified Capabilities

- `dashboard-shell` — a fourth view in the rail. The registry stays the one place that lists
